# Выявленые проблемы безопасности

1. Данные хранятся в незашифрованном виде (в виде эксель или файлового хранилища в 1С) на файловой системе, что может привести к их легкой краже.
2. Доступ к изменению данных не разграничен авторизационными политиками, что может привести к несанкционированным изменениям в данных.
3. Синхронизация данных между 1С Бухгалтерией и 1С Торговля и Склад, а также данных между ККМ и 1С Бухгалтерией производится не по зашифрованному протоколу данных, что может привести как к утеред данных, так и их изменению злоумышленником.
4. Данные хранятся вечно, несмотря на то что они могут быть больше не нужны
5. Есть избыточное накопление информации у бухгалтера (дублирует инфомрацию в эксель)
6. Нет аудита действий над данными

# Механизм тегирования

Для тегирования данных будем использовать Informatica Enterprise Data Catalog.
- Для тегирования эксель подключим jbdc конннектор к эксель ((инструкция)[https://www.cdata.com/kb/tech/excel-jdbc-informatica-edc.rst])
- Для тегрирования 1c будем писать свой коннектор к данным 


# Обеспечение защиты данных

- нужно настроить ролевую модель для доступа ко всем данных, например, с помощью Azure Active Directory
- нужно зашифровать все конфиденцильные данные
- при транспортировке писем будем использать SMTPS
- при транспортировке данных из ККМ в 1с бухгалтерию нужно обновиться на протокол поддерживающий tls1.2 +
- при синхронизации данных между 1с бухгалтерию и 1с склад нужно обновиться на протокол поддерживающий tls1.2 +
- удалить изыбточное накопление инфформации (эксель бухгалтера)
- при отправке анализов на обработку в лаборатории нельзя передавать персональный данные, мы должны просто навесить какой-то идентификатор пробирки и уже при получениее в наших системах связывать с пациентом
